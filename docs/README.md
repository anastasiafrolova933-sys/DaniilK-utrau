### Контроль свежести данных (с 2026-11-02)

**Зачем.** В ноябре 2026 выяснилось, что данные стояли 2+ месяца (доходность по 20.08, бюджет
по май, F&B по июнь, СПА по июль), а портал писал «Обновлено <сегодня>» — это было время
*сборки*, а не дата *данных*. Плюс `auto_update.ps1` выбрасывал вывод сборщиков (`Out-Null`),
поэтому «файл закрыт», «вкладка пустая» никто не видел, а push-дайджест падал с первого дня.

**Как теперь.** После каждой сборки `scripts/check_health.py` проверяет все 4 отчёта и пишет
`data/health.json`: по какую дату/месяц есть данные, насколько отстаёт, и список проблем.

| Отчёт | Ожидаем | ⚠️ / ❌ |
|---|---|---|
| Доходность | данные по вчера | > 3 дн. / > 7 дн. без новых строк |
| Бюджет | закрытый месяц к 25-му числу следующего | отстаёт на 1 / ≥ 2 мес. |
| F&B, СПА | закрытый месяц к 15-му числу следующего | отстаёт на 1 / ≥ 2 мес. |

Плюс в проблемы попадает всё, что нашли сборщики: файл F&B закрыт / не найден / неизвестный
формат, месяц не внесён в реестр, пустая вкладка СПА, нет колонки или нечитаемая ячейка
в доходности, сдвиг колонок бюджета, сборка не запускалась > 26 ч. Пороги — константы вверху
`check_health.py`.

**Где видно:**
- на портале — чип «данные по …» на каждой карточке, в отчётах «Данные по …» вместо
  «Обновлено …» и красная/жёлтая плашка с причинами (`js/freshness.js`);
- в `data/update.log` — полный вывод всех сборщиков и сводка проверки;
- в сообщении коммита: `Data update … | health: error (stale: finance 2026-08-20, …)`;
- push «⚠️ Утрау — данные не обновляются» (сразу при новой проблеме и раз в 3 дня, пока не
  починят). Отправка включается строкой `PUSH_ENABLED=1` в `backend/.env`, без неё — сухой
  прогон (в лог пишется, что ушло бы). Текст сводки (`health.json → text`) готов и для
  Telegram-бота.

Ручная проверка: `python scripts\check_health.py`. Тестовый прогон всего конвейера без git и
уведомлений: `powershell -ExecutionPolicy Bypass -File .\scripts\auto_update.ps1 -NoPush`.

### Telegram-бот сводок и ошибок @Utrau1_bot (с 2026-11-02)

**Для всех сотрудников, но только по одобрению.** Человек открывает https://t.me/Utrau1_bot и жмёт
Start. Администраторам приходит заявка с кнопками «✅ Разрешить / 👑 Админом / ❌ Отклонить». Пока
заявку не одобрили, бот цифр не показывает: ссылка на бота публичная, а в сводках финансы.

Администраторы бывают двух видов. Первые прописаны в `.env` (`TELEGRAM_ADMIN_IDS`) и снимаются
только там. Вторые назначены в боте кнопкой «👑 Админом» или командой `/admin ID` (роль хранится
в `tg_users.json`), снять — `/unadmin ID`. Кто сейчас администратор — команда `/users` в боте
(id и имена в README не пишем: репозиторий публичный).

| Кто | Что получает |
|---|---|
| Одобренные подписчики | сводку каждый день после обновления (~10:00): состояние 4 отчётов + последние цифры |
| Администраторы (`TELEGRAM_ADMIN_IDS` в `backend/.env`) | то же + заявки + «сбой обновления» (упал download/build или git push, со строками из лога) + «сегодня данные не обновлялись» (если к 11:30 не было проверки) |

Команды: `/report` — сводка сейчас, `/status` — подробно что устарело, `/stop` — пауза (`/start` —
вернуться). Администратору: `/users`, `/approve ID`, `/remove ID`.

**Файлы (`backend/`, не в git — там токен):**
- `utrau_bot.py` — процесс бота (long polling, `pythonw`), держит `127.0.0.1:8769` (второй экземпляр не
  стартует), пишет `tg_bot.heartbeat`, лог `tg_bot.log`;
- `notify_telegram.py` — рассылка из `auto_update.ps1` (шаг 5): `--daily` (не чаще раза в день,
  `--force`), `--pipeline …`, `--test` (сводка только администраторам), `--users`;
- `tg_common.py` — общее: API, подписчики, текст сводки (цифры считаются как на портале);
- `tg_watchdog.py` (основной, под `pythonw` — без мигающего окна) и `tg_watchdog.ps1` (запасной,
  для ручного запуска) — поднимают бота, если порт 8769 не слушается или пульс старше 5 мин
  (перезапуск **только владельца порта 8769**). Бот запускается **через WMI** (родитель
  `WmiPrvSE.exe`): Планировщик держит детей задачи в Job Object с `KILL_ON_JOB_CLOSE`, и бот,
  запущенный напрямую, умер бы вместе со сторожем;
- `tg_users.json` — подписчики и статусы (пишет только бот), `tg_daily_state.json` — когда была сводка.

**Автозапуск бота** — задача Планировщика `UtrauTelegramBot`, каждые 5 мин. Создана 02.11.2026
пользователем (Claude в автоматическом режиме задачи создавать не может). Вариант без мигающего
окна PowerShell — переключить действие задачи на pythonw:
```powershell
schtasks /change /tn UtrauTelegramBot /tr "C:\Users\CloudUser\AppData\Local\Programs\Python\Python312\pythonw.exe C:\Users\CloudUser\Desktop\DaniilK-utrau\backend\tg_watchdog.py"
```
Создать заново (на другом ПК) — `schtasks /create /tn UtrauTelegramBot /tr "<то же действие>" /sc minute /mo 5 /f`.
Ежедневная сводка уходит и без задачи: её шлёт `auto_update.ps1`, а не процесс бота. Новый
администратор: кнопка «👑 Админом» в заявке, `/admin ID` или id в `TELEGRAM_ADMIN_IDS` (бот
перечитывает `.env` сам).

### Как обновить данные (ежедневно)

Каждый день в 10:00 всё делает задача `UtrauDashboardUpdate` (см. «Автоматизация»), руками ничего не нужно.

**Вручную, без публикации:** двойной клик `update.bat` — скачает источники, пересоберёт отчёты,
проверит свежесть и зашифрует данные в `data/enc/` (это `auto_update.ps1 -NoPush`).

**Вручную, с публикацией на сайт:**
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\auto_update.ps1
```
Открытые `data/*.js` в git не попадают, уходит только `data/enc/` (см. «Вход и шифрование данных»).

**Что показывает:**
- Переключатель **БДР ↔ БДДС**
- 3 сценария: **Факт 2025 / План 2026 / Факт 2026** (факт — по май, далее пусто)
- KPI: выручка, затраты, операционная прибыль, прибыль до налога (БДР) / инвестиции (БДДС)
- Главное сравнение — **План 2026 vs Факт 2026** (% выполнения)
- Иерархическая таблица статей со сворачиванием (клик по ▸ = полная детализация подстатей)
- Графики: выручка план/факт по месяцам, структура выручки, операционная прибыль по месяцам

**Структура столбцов в таблице-источнике (важно для парсера):**
- Кол. 0-1: код статьи (1, 1.1, 1.1.1…) + название; Кол. 3-5: годовые Факт25/План26/Факт26
- Месяцы: каждый = 4 колонки (Ф25/П26/Ф26/%). **Раскладка разная:**
  - tab1 (БДР) имеет накопительные «2/3 месяца» → месяцы на 7,11,**18,25**,29,33,37,41,45,49,53,57
  - tab2 (БДДС) без накопительных → месяцы 7,11,**15,19**,23,27,31,35,39,43,47,51
  - **С 2026-11-02 позиции определяются по шапке** (блок месяца = «ФАКТ 2025 | ПЛАН 2026 |
    ФАКТ 2026»), поэтому вставка колонки в таблицу больше не сдвигает месяцы молча — в лог
    пишется «month columns moved to …». Массивы `$MONTHS_BDR`/`$MONTHS_BDDS` остались запасным
    вариантом: если шапку не распознать, они используются, а проверка свежести поднимает ❌.
  - CSV читается настоящим парсером (`TextFieldParser`): пояснение с переносом строки внутри
    ячейки больше не разрывает строку статьи (раньше её цифры терялись).
  - `budget_data.js` — валидный JSON внутри `window.UTRAU_BUDGET=…`, в нём `status`
    (последний месяц факта, раскладка колонок, предупреждения).

**Особенности данных (учтены в отчёте):**
- Строки-коэффициенты (доля в выручке, фудкост) и текстовые примечания помечаются `isRatio`
  и **исключаются** из дерева, т.к. проценты нельзя суммировать по периодам.
- Годовая ячейка Факт2026 может чуть отличаться от суммы месяцев (ручные корректировки в таблице).
- ADR в годовой ячейке Факт2026 в источнике битый (53 083) — в KPI не используется.

### Отчёт «F&B» (fnb.html) — Служба питания ресторана

**Схема с 2026-07: реестр + файл на месяц.** Каждый месяц = отдельный Google-файл (выгрузка iiko
OLAP, ресторан «КАЕФ»), вкладки внутри = категории продаж/списаний. Ссылки на файлы собираются
в **реестре-таблице**:

| Что | ID |
|-----|-----|
| Реестр F&B | `1ueE5blgChEYljlVnGktWKedsrcxfXXcn-U64X80AOQA` |

Реестр: колонка A = месяц (напр. «Июль 2026»), B = ссылка на файл месяца. **Новый месяц = вставить
строку (месяц + ссылка)**, файл открыть на «Доступ по ссылке → Просмотр». Код править не нужно.

**Парсер — Python** (`scripts/build_fnb.py`): читает реестр → качает XLSX каждого месяца →
**обходит ВСЕ вкладки** книги. Тип вкладки определяется по СТРУКТУРЕ: шапка «Блюдо / Сумма со
скидкой» → лист продаж; «Акты списания» → лист списаний. Категория — по имени вкладки, а для
списаний с мусорным именем (напр. «Лист1») — по колонке «Счёт списания». **Незнакомая вкладка не
теряется:** её сумма идёт в общий итог, а в лог падает предупреждение. Месяц берётся из реестра +
сверяется со строкой «Период:» внутри файла. Выход — `data/fnb_data.js` (window.UTRAU_FNB).

Из детализации собирается (сверено с прежней сводкой в копейку): выручка по типам, себестоимость,
фудкост (FC%), **7 категорий списаний**, топ блюд. **Типы для фильтра:** А-ля карт (кухня) / Бар
(напитки+алкоголь) / Банкеты (вкладка «Мероприятия») / Шведка-завтраки.

**Чего нет в выгрузке iiko** (заполняется опциональными колонками реестра по заголовку, иначе
на дашборде «не заведено»): аренда зала, пробковый сбор, услуги, товарный остаток, кол-во гостей
и средний чек (заголовки-триггеры: «аренда зала», «гости а-ля карт», «гости банкет», «товарный
остаток», «пробковый», «услуги»). Средний чек считается как выручка/гости, если гости заданы.
Детализация банкетов по заказчикам в новом файле отсутствует (блок показывает заглушку).

**Ежемесячно:** просто добавить ссылку в реестр. Пересбор — `python scripts/build_fnb.py`, вызов
уже в `download.ps1` (ежедневный цикл 10:00 — новые месяцы подхватываются сами). Фудкост (FC) =
себестоимость / выручка; норма 25-35%, выше 40% — внимание (в январе завтраки 43,2%).

**Статусы файлов реестра (с 2026-11-02)** — пишутся в `fnb_data.js → status` и на портал:
`ok` · `cache` (сегодня не скачался — показана последняя удачная копия из `data/fnb_raw/`,
месяц не пропадает с дашборда) · `no_access` (файл закрыт: владельцу открыть «Доступ по ссылке →
Просмотр») · `not_found` · `unknown_format` · `empty`. Строки реестра, где не распознан месяц
или нет ссылки, и дубли месяцев → `registry_issues` (раньше молча пропускались). Месяц можно
писать и «07.2026».

**Формат Sheet1 (март–июнь):** строки «Свободное блюдо» и «Сеты/пакеты» (себес «Сеты»)
относятся к а-ля карт (в iiko «Свободное блюдо» — группа КУХНЯ / МЕНЮ A LA CARTE). До 02.11.2026
они молча выпадали из разбивки: −523 тыс ₽ выручки и −55 тыс ₽ себеса за март–июнь. Теперь
себестоимость + списания каждого месяца сходятся с итогом самой таблицы («себес общий без
стафф» + стафф) до копейки. Любая незнакомая строка не теряется: идёт в «прочее» + ⚠️ в лог
и на портал. Если у файла формата A1/Sheet1 появится вторая непустая вкладка — тоже ⚠️.

### Отчёт «СПА / Банный комплекс» (spa.html)

**Одна Google-таблица** (`1eMzwZszovZ2AqIpaMS6PD-tvJvYdGZDD5DEaj8Qhu0w`) с **помесячными вкладками**
(доп. услуги ExtraServices): янв 2024 → текущий месяц. Каждая вкладка — простой список
«услуга → выручка за месяц».

**XLSX-подход (важно для автообновления):** `scripts/build_spa.py` скачивает **весь workbook как XLSX**
(`export?format=xlsx`) и парсит все вкладки openpyxl. Новые месяцы (июль+) подхватываются
**автоматически** — gid'ы не нужны, ничего добавлять руками.

**Определение месяца из имени вкладки** (имена хаотичные): сначала по суффиксу даты `_ДД.ММ.ГГГГ`
(вкладки 2024), иначе по русскому месяцу + год («Янв25», «декаб25», «Январь 2026»). Логика в
`detect_month()`.

**Категории** собираются из названий услуг по ключевым словам (`categorize()`): Баня / Банный комплекс,
Сауна и бассейн, Массаж, Парение и уход, Джакузи, Тарифы и прочее, Прочее — для консистентных трендов
(названия услуг сильно разнятся по месяцам).

**Дашборд:** фильтр по году (2024/2025/2026/Все) и месяцу; KPI (выручка за период, средняя/мес, услуг,

### Дашборд finance.html

**KPI-карточки** (6 штук):
- Доход за проживание — с дельтой к предыдущему году
- Загрузка % — средняя по периоду
- ADR — средняя цена: revenue / room nights
- RevPAR — revenue / available rooms
- Продано номероночей
- ALS — средняя длина пребывания

**Фильтры:**
- Год (кнопки — все доступные годы из данных)
- Период: Весь год / Q1 / Q2 / Q3 / Q4
- Месяц (выпадающий список)

**Графики:**
1. Выручка по месяцам — бары, все годы наложены
2. Загрузка % по месяцам — линии, все годы
3. ADR и RevPAR — двойная линия по месяцам
4. Выручка по дням недели — среднее, бары (выходные выделены)
5. Загрузка по дням недели — аналогично
6. Тепловая карта загрузки — calendar heatmap по дням года

**Сравнение периодов** (переключатель в фильтр-баре):
- Выбор Год A + месяц vs Год B + месяц
- Таблица: все 6 метрик, абсолютная и процентная дельта

**YoY-дельта в KPI — «сопоставимый период» (YTD):**
Если выбранный год неполный (напр. 2026 заполнен до 31 мая), дельта к предыдущему
году считается не от полного года, а от **того же отрезка дат** (1 янв – 31 мая 2025).
Иначе неполный год сравнивался бы с полным и давал бы заниженную дельту.
- Логика: `renderAll()` находит максимальную дату текущего года и обрезает
  предыдущий год по тому же `месяц-день` (функция `monthDay()`).
- Для завершённых лет (2024, 2025) обрезка не срабатывает — сравнение полное.
- Когда обрезка активна, на карточках выручки/загрузки выводится подпись
  **«vs ГГГГ (тот же период)»**, чтобы база сравнения была явной.
- Значение KPI остаётся фактическим YTD; обрезается только база дельты.

### Вход и шифрование данных (с 2026-11-02)

Репозиторий и GitHub Pages **публичные**. Раньше файлы данных лежали на сайте открыто: отчёты
открывались по прямой ссылке без пароля, а пароль сверялся с SHA-256 прямо в коде страницы.
Теперь пароль портала — это ключ, которым зашифрованы данные.

- **Сборка.** `scripts/encrypt_data.py` (шаг 3 `auto_update.ps1`) шифрует `data/*.js` и `health.json`
  в `data/enc/<имя>.enc`: AES-256-GCM, ключ = PBKDF2-SHA256(пароль, соль, 600 000 итераций).
  В `data/enc/meta.json` — соль, число итераций и контрольная строка для проверки пароля.
  Файлы, которые не изменились, не перешифровываются.
- **Браузер.** `js/secure.js`: на `reports.html` пароль проверяется расшифровкой контрольной строки,
  на устройстве сохраняется ключ (не пароль) — `localStorage['utrau_key']`, кнопка «Выйти» его стирает.
  Отчёт сначала расшифровывает свой файл и только потом выполняет основной скрипт страницы
  (`<script type="text/x-utrau">`). Нет ключа — переход на вход и обратно в отчёт.
- **Открытые файлы** (`data/*.js`, `*.json`, `*.csv`, `budget_raw/`) остаются на этом ПК — их читают
  Telegram-бот, push и `check_health.py` — и в git не попадают (`.gitignore`).
- **Пароль** — строка `PORTAL_PASSWORD` в `backend/.env` (не в git). Регистр, пробелы и дефисы
  при вводе не важны.

**Сменить пароль** (например, ушёл сотрудник): вписать новый в `PORTAL_PASSWORD` и запустить
`powershell -ExecutionPolicy Bypass -File .\scripts\auto_update.ps1` (или дождаться 10:00).
Соль сменится, всё перешифруется, и портал у всех попросит новый пароль. Пароль — не короче
12 символов: шифротекст лежит в открытом репо, короткий пароль можно подобрать перебором.

**Проверить локально:** `python -m http.server 8777` в папке проекта → http://localhost:8777/reports.html
(с `file://` не работает: браузер не даёт читать файлы через fetch).

### Автоматизация через Task Scheduler — НАСТРОЕНА ✅

Ежедневное обновление работает автоматически, как у портала Baden.

**Задача:** `UtrauDashboardUpdate`
**Расписание:** каждый день в 10:00
**Что делает:** запускает `scripts/auto_update.ps1`, который:
1. Скачивает все источники и пересобирает 4 отчёта (`download.ps1`) — весь вывод в лог
2. Проверяет свежесть (`check_health.py` → `data/health.json`)
3. Шифрует данные для сайта (`encrypt_data.py` → `data/enc/`, см. «Вход и шифрование данных»)
4. `git add data/` (уходит только `data/enc/`) + `git commit` + `git pull --rebase --autostash` + `git push` → сайт обновляется сам
5. `backend/notify_push.py` — тревога «данные не обновляются» / дайджест (см. «Контроль свежести»)
6. `backend/notify_telegram.py` — сводка в Telegram и тревога администраторам о сбое (см. «Telegram-бот»)

Ручной запуск меня (Claude) **не требуется** — всё крутится через Планировщик Windows.
Git-push использует учётные данные из Windows Credential Manager (уже сохранены).

**Лог:** `data/update.log` (последние запуски, успех/ошибки). В git не попадает.

**Проверить статус задачи:**
```powershell
Get-ScheduledTaskInfo -TaskName "UtrauDashboardUpdate"   # LastTaskResult 0 = успех
```

**Запустить вручную сейчас:**
```powershell
Start-ScheduledTask -TaskName "UtrauDashboardUpdate"
```

**Изменить время запуска / частоту:**
```powershell
$t = New-ScheduledTaskTrigger -Daily -At 09:00
Set-ScheduledTask -TaskName "UtrauDashboardUpdate" -Trigger $t
```

**Пересоздать задачу с нуля** (если перенесли проект в другую папку):
```powershell
$action = New-ScheduledTaskAction -Execute "powershell.exe" `
  -Argument '-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\НОВЫЙ_ПУТЬ\DaniilK-utrau\scripts\auto_update.ps1"'
$trigger = New-ScheduledTaskTrigger -Daily -At 10:00
Register-ScheduledTask -TaskName "UtrauDashboardUpdate" -Action $action -Trigger $trigger -Force
```

> При переносе на другой ПК задачу нужно пересоздать (путь к скрипту меняется).
> На исходном компьютере она уже работает.

### ИИ-чат + Push-уведомления + PWA

В отчёты `finance.html` и `budget.html` встроен **ИИ-консультант** (кнопка ✦ внизу справа),
а на всех страницах — кнопка **«🔔 Уведомления»** (вверху справа): установка на экран «Домой»
и push-уведомления.

**Архитектура (серверная, по образцу Baden — но полностью изолирована):**

```
backend/  (НЕ в git — секреты; лежит в папке, но не публикуется)
├── chat_server.py     — aiohttp: /chat (Claude), /health, /api/push/*
├── config.py          — отчёты + системные промпты (finance, budget)
├── .env               — ANTHROPIC_API_KEY (копия ключа Баден), VAPID, INTERNAL_PUSH_TOKEN
├── gen_vapid.py       — генерация VAPID-ключей (разово)
├── gen_icons.py       — генерация PWA-иконок (разово)
├── notify_push.py     — дайджест + аномалии → web-push (вызывается из auto_update.ps1)
├── start_server.ps1   — cloudflared-туннель + сервер + публикация URL в api_url.json (+git push)
├── watchdog.ps1       — каждые 15 мин: если /health лёг → запуск UtrauChatServer
├── cloudflared.exe    — туннель
└── subs.db            — push-подписки (SQLite)
```

**Фронт (в git, на сайте):** `chat-widget.js`, `js/pwa.js`, `notify.js`, `sw.js`,
`manifest.json`, `api_url.json` (URL туннеля), иконки `icon-*.png`, `apple-touch-icon.png`.

**Модели:** Haiku 4.5 (простые вопросы) / Sonnet 4.6 (аналитика — авто-переключение).
Чат видит данные открытого отчёта через `window.__reportData()` на странице.

**Порт:** 8768 (8765 = лояльность Баден, 8766 = чат Баден). Туннель cloudflared даёт
динамический `https://*.trycloudflare.com`, который меняется при каждом перезапуске —
поэтому `start_server.ps1` сам обновляет `api_url.json` и пушит на GitHub Pages.

**Задачи Планировщика:**
- `UtrauChatServer` — ежедневно 06:00 (свежий туннель к утру) + по требованию (`schtasks /run`)
- `UtrauChatWatchdog` — каждые 15 мин, перезапускает сервер если `/health` недоступен

**Push-уведомления** (выбраны все три типа), шлёт `notify_push.py` после ежедневного
обновления данных (вызов добавлен в `auto_update.ps1`):
- 🌿 **дайджест** за день (выручка/загрузка + с начала месяца) — он же «данные обновлены»
- ⚠️ **аномалия** (critical) — если загрузка дня отклонилась ≥35% от среднего за неделю

**Включение push на iPhone** (iOS 16.4+): Safari → «Поделиться» → «На экран Домой» →
открыть приложение с экрана → «🔔 Уведомления» → «Включить». Инструкция зашита в модалку.
